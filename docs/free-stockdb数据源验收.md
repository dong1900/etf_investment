# free-stockdb ETF 数据源验收

验收日期：2026-08-29
验收对象：free-stockdb Windows Release `v0.3.2 more-power`（Release 标签：`测试0.3.2`）
本地安装：`C:\tools\free-stockdb\app\stockdb`
本地数据：`C:\tools\free-stockdb\app\stockdb\data`

## 结论

**阶段性结论：保留为当前 ETF 研究可选的本地数据工具，按具体研究标的进行覆盖校验；暂不因少量异常判定整体不可用。**

本地查询性能、基础代码正确性和日K主要字段均已通过；本次抽样发现 518880、510880、159903 等少量老 ETF 的历史从 2024-01-02 才开始，而同类老黄金 ETF 和多数抽查老 ETF 的历史完整。这说明具体标的存在历史缺失，需要在实际筛选或回测前逐只校验；但当前不能据少量异常外推为全市场不可用。

当前阶段，若同一指数存在其他历史完整 ETF，应直接替代研究；必要时再以其他免费数据源补充。只有当缺失明显影响筛选、回测或当前投资决策时，才重新评估 free-stockdb 的使用范围。若未来需要读取本地库，最小边界仍可为：

```text
ETF 项目（只读适配器）
  -> localhost:7899 的 free-stockdb HTTP/Python 接口
  -> 本地 free-stockdb 数据库
```

实际研究时应进行代码—名称—交易所、最早日期与最新交易日的最小校验；本次未开发正式数据层。

## 字段、单位与复权

日K字段实测包含：

```text
date, code, name, open, high, low, close, volume, amount,
turnover, pre_close, pct_chg, amplitude,
total_share, float_share, total_mv, float_mv, is_st, vol_ratio, pe_ttm, pb
```

- 没有独立的 `change` 字段；涨跌幅字段为 `pct_chg`。
- `pre_close` 在正常连续交易记录中存在，但历史首行可能为空，调用方不能假设始终非空。
- `volume` 的数值口径实测为股：例如 510300 在 2026-08-28 为 604,693,300。
- `amount` 的数值口径实测为元：同日为 2,835,120,000，`amount / volume = 4.688526`，与当日价格 4.679 接近，符合“股 × 成交均价（元）”。官方文档未明确写出单位，此结论基于数值核验。
- `turnover` 为百分比数值，例如 2.56 表示约 2.56%。

`get_data()` 默认 `fq='qfq'`，即前复权；`fq=None` 返回原始不复权行情；`fq='hfq'` 返回后复权。510300 在本地 `复权` 表中有 14 条因子记录，字段含 `div/give/trans/mult/cum`。2016-06-01 的原始收盘价为 3.156，前复权为 2.646，后复权为 3.358，三种结果存在实际差异。

官方代码表明 SDK 在客户端读取 `复权` 表后动态换算 OHLC 与 `pre_close`。但 ETF 分红如何纳入、因子具体来自哪个上游、因子是否完整，官方资料未说明；因此保留结论：**复权语义待确认**。

## 更新机制与数据来源

Release 的 `sync_url.txt` 默认配置了 `https://ah.123128.xyz` 与 `https://ad.123128.xyz`。它们是镜像/同步节点，而非被官方文档说明的原始行情提供方。项目 README 与 `docs/DATA_SOURCE.md` 明确将 free-stockdb 定位为本地数据管理/查询引擎，数据源可由镜像或自建节点替换；未披露默认镜像的原始行情上游、授权或再分发安排。

当前 Release 写入的 `.sync_manifest.json`（version 2）对每个文件保存路径、大小、mtime、fast hash 和 SHA-256。开源同步器文档及实现说明：

1. 已存在文件若大小和 SHA-256 一致则跳过；
2. 不一致时写入 `*.part`，校验大小和 SHA-256 后替换；
3. 同步 LevelDB 快照时应停止本地服务，完成后再启动；
4. 开源实现会在重新同步时删除原有 `.part` 后重新获取完整文件，未证实字节级断点续传。

本次不能安全复跑更新器：它可能改写现有 21.436 GiB 数据库，与“不要修改 free-stockdb 数据文件”的验收边界冲突。因此以下项目为待确认，而非通过：

- 已有 674 个文件是否全部被 Release 更新器跳过；
- 实际增量下载字节数、耗时、失败后重试行为；
- 下一交易日新增日K的写入时点与是否重复下载；
- Release 更新器是否真正支持断点续传。

**待下一交易日进行最终增量验证。** 该验证应先记录清单文件数/总字节/哈希摘要，停止本地服务，运行一次更新器，记录其日志与新增/变更文件，再重新启动服务并验证新的日K日期；不应伪造或手工修改数据库。

## 当前使用边界

- 已发现少量老 ETF 的历史从 2024 年起截断；具体标的进入研究前需校验最早日期。
- 实际同步量为 21.436 GiB 且含分钟K，后续如存储控制影响项目推进，再按需要评估。
- 默认镜像的上游行情来源、数据许可、ETF复权因子来源和分红语义未公开说明；当前仅记录，不继续扩大调查。
- Release 更新器使用的 JSON 清单与开源文档中的 `manifest.txt` 协议不一致；当前保留“待下一交易日最终增量验证”。
- Investing.com 样本未找到，OHLCV 逐日交叉验证待有现成样本时补做。

本验收到此收口：free-stockdb 可在后续具体 ETF 研究中按需使用；若同指数有历史完整 ETF 则优先替代，必要时再补数。除非历史缺失实际阻塞筛选、回测或投资决策，不再继续扩大数据完整性调查。
