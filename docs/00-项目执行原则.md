# ETF 投资辅助工具项目执行原则

> 文档性质：项目执行宪章。ChatGPT / Work / Codex 每次分析、设计、开发、调查前必须优先阅读；它不是新的需求说明或技术设计。

## 1. 最终目标

本项目不是行情数据库、专业量化平台、自动交易系统，也不为了技术完整性建设数据平台。

项目只需要持续回答三个问题：

1. 买什么？
2. 怎么买？
3. 今天要不要操作？

任何新增工作原则上必须直接服务于至少一个问题。

## 2. 投资研究主线

始终按以下顺序推进：

投资方向 / 指数 → 判断长期投资价值 → 选择代表 ETF → 验证投资策略 → 形成实际投资计划 → 根据最新数据和实际持仓判断今天是否操作。

不得因为某只 ETF、某个数据源或某个技术问题改变项目主线。

## 3. 投资范围

正式定投 / 定投+网格研究仅限于具有明确指数或客观资产价格跟踪规则的被动 ETF，包括宽基、行业/主题、Smart Beta / 规则型、港股/海外指数、黄金等明确客观资产，以及其他符合该原则的指数型产品。

不研究依赖基金经理主动选股、择时或主观配置的产品。

## 4. 数据只是工具

目标不是建设 100% 完整的 ETF 行情数据库。数据只需足以支持投资方向筛选、代表 ETF 选择、策略回测和当前投资决策。

少量 ETF 历史缺失时，优先判断同指数是否有其他可用 ETF；有则直接替代研究；必要时再通过其他免费数据源补充。不要因为少量数据异常自动扩展为全市场数据治理工程。

只有当缺失已明显影响筛选、回测或投资决策，才重新评估主数据源。

## 5. 简单优先

多个方案都能满足目标时，优先选择更简单、参数更少、数据依赖更少、人工维护更少、更容易理解且更容易长期执行的方案。

理论上更完整，不等于本项目中更优。

## 6. 防跑偏检查

开始任何新调查、设计或开发前，必须回答：

1. 当前任务服务于“买什么 / 怎么买 / 今天做什么”中的哪一个？
2. 如果现在不做，会不会阻塞当前阶段继续推进？
3. 有没有明显更简单的解决方式？
4. 当前是在解决项目问题，还是已经开始解决工具自身的问题？

若任务不能直接服务项目目标且不阻塞当前阶段：记录 → 暂缓 → 回到主线。

## 7. 范围扩张规则

执行中发现新问题时，不得自动扩大任务范围。先判断其是否阻塞当前任务、是否明显影响最终投资决策；若都不是，记录为非阻塞问题，不继续深入。需要明显扩大范围时，交由用户确认。

## 8. AI 协作职责

- 用户：产品负责人和最终决策者。
- ChatGPT / Work：目标控制、需求分析、架构设计、方案评审、任务拆分和结果审核。
- Codex：调查、实现、测试和文档维护。

ChatGPT / Work / Codex 都必须遵守本执行原则，不得因一个技术问题自行将其升级为新的项目主线。

## 9. 每次任务执行规则

开始任务时，必须先阅读：

1. `docs/00-项目执行原则.md`
2. 与当前任务直接相关的正式需求或设计文档。

执行中如范围明显扩大，重新检查本原则。任务结束时增加简短“执行原则复核”，回答：本次解决了什么、是否仍直接服务当前主线、是否产生新的非阻塞问题、是否已经可以停止继续深入、下一步最小必要动作是什么。

## 10. V1 停止原则

V1 追求“够用、可靠、可长期执行”，不是理论最优。当系统已经能够可靠回答“买什么 → 怎么买 → 今天做什么”时，V1 即达到主要目标。

不要因为数据更全、模型更复杂、参数更多、报告更漂亮或架构更先进，而无限延迟可用版本。
