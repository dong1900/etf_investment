## 1. 项目目标与边界

### 1.1 项目定位

本项目是供个人长期使用的 ETF 投资辅助工具，服务于沪深市场 ETF 的筛选、策略判断、历史验证和定期检查。项目不是专业量化交易平台，也不面向公众提供投资服务。

项目不是：

- 专业量化研究平台；
- 高频交易系统；
- 自动交易系统；
- AI 预测涨跌系统；
- 面向公众的投资服务。

### 1.2 核心目标

V1 形成以下可长期执行的闭环：

全市场 ETF → 小规模投资池 → 为每个标的确定策略 → 历史验证策略 → 定期更新数据 → 输出明确行动建议。

工具的核心结果是帮助用户判断：当前是否需要操作、操作什么、涉及哪个标的以及触发原因。

### 1.3 V1 正式策略范围

V1 最终投资策略状态统一为：

- 定投；
- 定投 + 网格；
- 观察 / 暂不投资。

动态定投属于定投策略内部的一种实现方式，不作为与“定投”并列的最终投资状态。纯网格不作为 V1 独立正式投资策略，网格只能作为长期投资标的的可选增强模块。

### 1.4 工具职责

- 从全市场 ETF 中形成小规模投资池；
- 判断投资方向的长期投资价值；
- 为投资方向选择代表 ETF；
- 判断各标的适合的正式策略状态；
- 使用历史数据验证策略；
- 定期检查行情、策略状态和实际持仓；
- 结合最新数据、已确认策略和实际持仓，输出明确、可解释的行动建议；
- 不存在行动事项时明确输出“无需操作”。

### 1.5 用户职责

- 决定是否采纳工具建议；
- 维护实际持仓、持仓成本以及策略执行所必需的信息；
- 在银河证券、川财证券或同花顺中手动执行交易；
- 记录实际执行结果；
- 对最终投资决策和结果负责。

用户不被要求必须维护可投资资金；只有在后续策略确实需要时，才维护相应资金信息。

### 1.6 系统边界

- V1 不自动下单；
- V1 不连接券商执行交易；
- V1 不自动同步券商账户；
- V1 不追求实时、高频或日内交易；
- V1 不以预测短期涨跌为目标；
- V1 不承诺收益；
- V1 不代替用户进行最终投资判断；
- V1 不建设通用量化研究平台。

## 2. 三层决策逻辑与核心流程

### 2.1 买什么

由长期投资价值筛选解决：哪些投资方向值得长期关注、哪些方向进入正式投资池，以及每个方向选择哪一只代表 ETF。

### 2.2 怎么买

由策略历史验证解决：采用定投还是定投 + 网格，动态定投是否值得采用，网格是否具有足够增量价值，以及哪些方向应处于观察 / 暂不投资状态。

### 2.3 今天做什么

由最新市场数据、当前投资计划、用户实际持仓、已执行操作和已确认策略共同决定当天是否存在行动事项。

### 2.4 核心流程

全市场 ETF → 识别并归并投资方向 → 判断长期投资价值 → 形成候选方向 → 选择代表 ETF → 建立固定定投基准 → 验证动态定投 → 验证网格增量价值 → 确定正式策略 → 形成投资计划 → 维护持仓与执行记录 → 交易日每日检查 → 输出行动建议 → 低频重评投资池。

不得每日重新筛选长期投资池。

## 3. 投资范围

### 3.1 基础研究范围

V1 原则上研究沪深交易所上市、普通个人投资者能够正常交易的 ETF，包括：

- A 股宽基 ETF；
- 行业 ETF；
- 主题 ETF；
- Smart Beta / 策略指数 ETF；
- 港股相关 ETF；
- 境外指数 ETF；
- 黄金等适合长期投资研究的商品 ETF；
- 债券 ETF。

### 3.2 可直接排除的产品

- 货币 ETF；
- 已退市产品；
- 长期无法正常交易的产品；
- 交易状态异常的产品；
- 明显不符合长期个人投资目标的特殊产品。

### 3.3 研究范围与投资池

研究范围不等于正式投资池。不得仅因主观认为某一类资产不值得投资，就在正式数据分析前直接排除；应先纳入统一研究范围，再依据统一规则筛选。

## 4. 投资方向与 ETF 产品分工

### 4.1 概念区分

- ETF 产品：某一只具体 ETF，包括代码、名称和产品信息；
- 投资方向：ETF 所代表的指数、资产类别或高度相似的一组投资暴露；
- 代表 ETF：一个投资方向最终用于实际交易和策略执行的 ETF。

### 4.2 数据分工

长期投资价值判断优先基于跟踪指数、对应资产或能够代表该投资方向的长期历史数据。

具体 ETF 产品主要用于流动性、规模、跟踪质量、费率、存续稳定性、实际交易和策略回测。

ETF 上市时间较短时，不应仅因为 ETF 自身历史不足，就直接否定其对应投资方向。ETF 历史和指数 / 资产历史必须明确区分展示。

## 5. 投资池筛选规则

### 5.1 投资池目标

形成规模较小、方向明确、重复度低、适合长期跟踪且能够实际执行的正式投资池。

原则上目标约为 10～20 个投资方向，但不是硬性数量要求，不得为了凑数量降低标准。

### 5.2 核心筛选因素

- 历史长度；
- 流动性；
- 长期收益能力；
- 最大回撤；
- 长期稳定性；
- 与已有方向的重复程度。

### 5.3 入选判断

每个投资方向必须能够解释长期收益是否合格、最大回撤是否可接受、滚动收益是否稳定、历史数据是否足够、是否与已有方向高度重复，以及为什么纳入、观察或暂不投资。

不得只生成一个无法解释的综合分数作为唯一结论。正式阈值应配置化并能够说明依据。

### 5.4 研究池与正式投资池

- 研究池用于长期跟踪、保留研究记录和支持后续重评；
- 正式投资池用于形成实际投资计划和日常策略检查；
- 正式投资池中的方向可以转为观察 / 暂不投资，但默认仍保留在研究池；
- 只有存在明确结构性失效原因时，才真正从研究池移除。

## 6. 同类去重与代表 ETF 选择

### 6.1 去重依据

优先依据跟踪指数、指数底层成分、投资方向以及长期价格或收益走势相似性。相关性可以作为辅助工具，但不得仅依据单一固定相关系数完成全部分类。

### 6.2 去重要求

最终投资池不得出现大量本质相同的 ETF。系统应能够解释为什么两个 ETF 属于同一投资方向、为什么应合并，或为什么仍应分别保留。

### 6.3 代表 ETF 选择因素

- 流动性；
- 基金规模；
- 跟踪质量；
- 费率；
- 产品存续稳定性；
- 数据完整性。

## 7. 长期投资价值指标

### 7.1 历史长度

展示数据开始日期、数据结束日期、总交易日和可用历史年数。

### 7.2 收益指标

至少展示全历史累计收益、最近 1 年收益、最近 3 年收益、最近 5 年收益、全历史 CAGR、最近 3 年 CAGR 和最近 5 年 CAGR。

长期投资价值判断优先使用 CAGR。历史不足时不得强行计算，必须明确标记。

### 7.3 年度收益

逐自然年度统计年度收益，并计算年度平均收益、年度收益中位数、正收益年份比例、最好年度、最差年度及当前年度 YTD 收益（数据充足时）。年度平均收益仅作为辅助理解指标，长期判断以 CAGR 和滚动收益为主。

### 7.4 风险指标

至少展示全历史最大回撤、最大回撤开始时间、最大回撤最低点、回撤恢复时间、是否已经恢复、当前回撤和统一口径的年化波动率。当前回撤不能单独作为买入依据。

### 7.5 长期稳定性

至少计算 3 年和 5 年滚动收益，并展示滚动收益中位数、最差滚动收益、最好滚动收益和滚动正收益比例。历史不足时只计算满足窗口的数据，并明确标记样本不足。

## 8. 收益与回测口径

### 8.1 长期价值评价

投资方向长期价值评价使用 CAGR。长期收益应优先使用能够反映分红再投资的总收益口径。

如果只能获取价格收益数据，必须明确标记为“价格收益”，不得与总收益口径直接混淆比较。

### 8.2 现金流策略回测

定投、动态定投、定投 + 网格等现金流策略回测使用 XIRR。总收益率作为辅助指标。

ETF 实际交易策略回测应使用真实可交易价格，并明确分红如何处理、复权口径、手续费、交易成本及其他影响结果的处理方式。具体数值参数可以配置，但口径必须统一、可解释、可复现。

## 9. 策略体系与定投策略

### 9.1 正式策略状态

| 策略状态 | 含义 |
|---|---|
| 定投 | 采用定投作为正式投资方式 |
| 定投 + 网格 | 以定投为基础，并启用经验证的网格增强 |
| 观察 / 暂不投资 | 暂不执行新增投资，继续观察或等待人工确认 |

### 9.2 固定定投基准

每个正式投资方向首先建立固定周期、固定金额、固定执行规则的定投基准。

### 9.3 动态定投

动态定投是定投策略内部的可选实现方式。可以研究少量、简单、可解释的状态调整。不得预先规定必须使用价格分位、均线、趋势、PE、PB 或复杂评分。只有相对固定定投具有明显实际价值时，才允许采用动态规则。

### 9.4 简单策略优先

如果复杂策略相比固定定投的收益改善很小，却带来更多操作、参数、资金管理、数据依赖或过拟合风险，则优先使用固定定投。

## 10. 网格策略

### 10.1 使用前提

网格只能用于已经通过长期投资价值筛选的投资方向，不能因为网格潜力将方向加入正式投资池。

### 10.2 参数研究范围

网格只研究实际执行所必需的少量参数。V1 不预设中枢、过滤器、启动机制、暂停机制或其他参数必须存在；只有某项参数确实影响实际执行并通过验证，才纳入正式规则。

### 10.3 启用条件

至少比较固定定投、最终定投规则和定投 + 网格。如果网格收益提升不足、回撤恶化、资金效率下降、操作次数显著增加或结果严重依赖参数，则不开启网格。

纯网格不作为 V1 独立正式策略。

## 11. 历史验证与策略回测

### 11.1 回测目标

回测用于判断规则是否值得长期执行，不用于证明策略一定赚钱。

### 11.2 策略对比

每个最终 ETF 至少提供：

| 策略 | 总投入 | 最终资产 | 总收益率 | XIRR | 最大回撤 | 操作次数 | 最大资金占用 | 网格 / 现金预留需求 | 资金闲置情况或利用率 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 固定定投 |  |  |  |  |  |  |  |  |  |
| 动态定投 |  |  |  |  |  |  |  |  |  |
| 定投 + 网格 |  |  |  |  |  |  |  |  |  |

未采用的策略标记为“不采用”，并说明原因。

### 11.3 资金效率

必须考虑最大资金占用、网格或现金预留需求、资金闲置情况和资金利用率。如果定投 + 网格长期占用大量预留现金，即使表面收益较高，也不应自动认定为更优策略。

### 11.4 回测约束

必须避免使用未来数据、单一 ETF 过度拟合、只展示有利标的或区间、忽略交易成本和忽略实际资金约束。不得为了获得更好的回测结果持续增加指标、参数、过滤条件或分析链。

## 12. 当前投资计划、持仓与执行记录

### 12.1 当前投资计划

系统必须生成独立于研究报告的当前投资计划。

| 投资方向 | ETF | 当前策略 | 基础投入计划 | 网格状态 | 当前持仓 | 当前成本 | 当前状态 |
|---|---|---|---:|---|---:|---:|---|
|  |  |  |  |  |  |  |  |

投资计划来源于投资池、最终策略和用户实际配置。

### 12.2 实际持仓

至少记录账户、ETF 代码、持有份额和持仓成本。只有确实影响行动建议时，才增加已投入资金、可投资资金、网格占用资金、单标的资金上限、最近一次定投或当前网格状态等字段。

### 12.3 实际执行记录

系统必须允许用户确认建议是否已经执行，并记录对应建议、实际执行日期、实际成交份额或金额、实际成交价格和备注。系统不得默认所有建议都已执行，后续判断必须基于实际执行结果。

## 13. 定期运行与投资池重评

### 13.1 投资池低频重评

投资池重评用于判断投资方向是否仍值得长期投资，属于低频任务，具体采用月度或季度频率。

重评首先允许以下结论：继续持有、继续新增、停止新增、转观察、需要人工复核。

正式投资池中的方向转为观察时，默认仍保留在研究池。只有存在明确结构性原因时，才从研究池移除，例如指数或投资方向失去代表性、产品退市或长期无法交易、投资逻辑发生实质变化，或与其他方向确认高度重复且无继续保留价值。

不得因为短期收益差、短期趋势弱或一次重评结果变差，就频繁移除长期方向。

### 13.2 每日策略检查

交易日每日检查最新数据、当前策略、当前投资计划、实际持仓和执行记录，判断当天是否存在行动事项。每日策略检查不得重新筛选长期投资池，也不得因短期价格波动频繁更换长期投资方向。

### 13.3 每日运行流程

更新最新数据 → 检查数据完整性 → 读取投资池和投资计划 → 读取实际持仓和执行记录 → 运行当前策略 → 生成行动建议 → 保存每日策略报告。

### 14.2 单标的详细报告

每个最终投资方向必须提供投资方向、ETF 代码和名称、跟踪指数或资产、上市日期、历史数据区间、当前策略、收益口径、全历史累计收益和 CAGR、最近 1/3/5 年收益及 CAGR、年度收益、年度平均收益、年度收益中位数、正收益年度比例、最大回撤、当前回撤、年化波动率、3 年/5 年滚动收益、滚动正收益比例、入选原因、代表 ETF 选择原因、主要风险和数据限制。

### 14.3 单标的图表

每个最终投资方向至少提供长期净值或价格增长曲线、历史回撤曲线、年度收益柱状图、3 年滚动收益曲线、数据充足时的 5 年滚动收益曲线、策略资产曲线和策略回撤曲线。长期增长曲线建议将起点标准化为 100。

### 14.4 投资池比较图

至少提供收益与回撤散点图（横轴为最大回撤、纵轴为长期 CAGR）、各标的 CAGR 对比柱状图和各标的最大回撤对比柱状图。

|  |  |  |  |  |  |  |

无行动时明确显示：**今日无需操作**。

任何建议至少说明触发原因、使用的策略规则、当前指标、对应阈值、当前持仓以及未执行时的后续提示逻辑。

### 14.6 投资池重评报告

至少说明方向是否继续保留、是否继续新增、是否停止新增、是否转为观察、是否需要人工复核、代表 ETF 是否仍合适，以及调整或移除的依据。

## 15. 数据需求与数据源原则

### 15.1 数据最小化

只有能够直接支持投资方向筛选、ETF 产品选择、策略选择、历史验证、每日操作或持仓状态判断的数据才纳入 V1。不得因为“以后可能有用”而大量增加数据。

### 15.2 基础数据

预计需要 ETF 代码、名称、上市时间、跟踪指数或资产、产品类型、交易状态、日频价格数据、日频成交数据，以及必要时的指数或对应资产长期历史数据。日频行情字段根据最终策略实际需要确定。

### 15.3 数据质量

需要识别缺失日期、重复记录、异常价格、成交数据异常、产品状态变化、数据源更新失败，以及 ETF 历史与指数 / 资产历史混淆。核心数据获取失败时，应明确停止相关判断，不得使用不可靠数据继续生成建议。

### 15.4 数据源要求

数据源应可重复获取、相对稳定、字段含义明确、可自动更新且数据质量可验证。V1 不建立复杂的数据源容灾系统。

## 16. 验收标准

V1 完成后，用户必须能够：

1. 查看投资池总览，知道目前值得长期投资哪些方向；
2. 查看每个标的的 CAGR、最近 1/3/5 年收益、年度收益、最大回撤、当前回撤、滚动收益和波动率；
3. 查看长期增长曲线、回撤曲线、年度收益柱状图和 3 年/5 年滚动收益曲线；
4. 查看投资池收益与回撤横向比较图；
5. 理解每个方向为什么入选；
6. 理解为什么选择当前 ETF 作为代表产品；
7. 知道每个标的采用定投、定投 + 网格，还是观察 / 暂不投资；
8. 查看固定定投与最终策略的回测对比；
9. 评估策略的最大资金占用、现金预留和资金利用率；
10. 查看当前投资计划；
11. 维护实际持仓和策略执行记录；
12. 每个交易日查看当天是否需要操作；
13. 无行动事项时看到“无需操作”；
14. 通过低频重评报告判断投资池是否需要调整。

达到上述能力后，V1 停止继续扩展，进入实际使用阶段。

## 17. V1 明确不做的内容

V1 不做：

- 自动下单；
- 券商交易接口；
- 同花顺自动化；
- 高频交易；
- 日内交易；
- 分钟级行情；
- AI 预测涨跌；
- 机器学习选 ETF；
- 新闻情绪交易；
- 宏观预测交易；
- 个股分析；
- 专业资产配置系统；
- Web 应用；
- 手机 App；
- 多用户；
- 云端账户体系；
- 纯网格独立正式策略；
- 无限参数搜索；
- 为提高回测收益不断增加规则；
- 为每个问题持续创建新的分析链；
- 直接复用旧 `etf_strategy` 项目的代码、数据、配置、结果或需求设计。

## 18. Git 与需求控制原则

整个项目纳入本地 Git 管理，用于追踪需求、策略、源码、配置、测试和正式结果变化。

讨论稿不提交。确认后的正式需求和正式实现才提交。每个具有独立意义、可以独立验证的阶段创建一次有明确含义的中文提交。

以后任何新增数据、指标、参数、过滤条件、分析模块、回测、图表、报告或功能，都必须回答：

> 它是否会直接改变“买什么”“怎么买”或“今天做什么”？

如果不能明确回答“会”，V1 默认不增加。不得为了回测结果持续增加指标、参数、过滤条件或分析链。
